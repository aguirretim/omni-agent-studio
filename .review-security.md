## Critical Findings

### S1 — REPEAT (C1) — Shell Injection via commit message
**Severity:** Critical
**File:** `app/api/commit/route.ts:32`
**Description:** User-supplied `message` flows directly into a shell-interpolated string passed to `exec()`. A message like `"; rm -rf ~/ #"` breaks out of the double-quote context and executes arbitrary OS commands in `projectPath`.
```ts
// VULNERABLE:
const commitMsg = message || `Session close: ${new Date().toISOString()}`;
await execPromise(`git commit -m "${commitMsg}"`, { cwd: projectPath });
```
**Fix:** Replace with `spawn` using an argument array, `shell: false`:
```ts
spawn('git', ['commit', '-m', commitMsg], { cwd: projectPath, shell: false });
```

### S2 — REPEAT (C2) — Shell Injection via projectPath in terminal route
**Severity:** Critical
**File:** `app/api/terminal/route.ts:43`
**Description:** `projectPath` is user-supplied and flows directly into `winCmd` string concatenation passed to `exec()`. Although `command` is whitelisted (lines 17–18), a path like `C:\test" && calc.exe && echo "` escapes the quotes and injects arbitrary cmd.exe commands. The whitelist provides zero protection against this vector.
```ts
// VULNERABLE:
const winCmd = `start "OmniAgent - ${command}" cmd.exe /K "cd /d ${projectPath} && ..."`;
exec(winCmd, ...);
```
**Fix:** Write a `.bat` file with properly quoted contents, then `exec('start "" <file.bat>')`, or use `spawn` with an args array and `shell: false`.

### S3 — REPEAT (C3/C4) — Shell Injection via ps1Path/scriptWslPath in exec strings
**Severity:** Critical
**File:** `app/api/agent-teams/route.ts:1141, 1168, 1174`
**Description:** `ps1Path` and `scriptWslPath` are derived from user-supplied `projectPath` via `path.join`, then embedded inside double-quoted `exec()` shell strings. A `projectPath` containing `"` or cmd.exe metacharacters breaks out of the argument boundary.
```ts
// VULNERABLE — line 1141:
exec(`wt.exe --title "Agent Team" wsl.exe bash "${scriptWslPath}"`, ...)
// VULNERABLE — line 1168:
exec(`wt.exe -- powershell -NoExit -ExecutionPolicy Bypass -File "${ps1Path}"`, ...)
// VULNERABLE — line 1174:
exec(`start "Agent Team - Claude Code" powershell -NoExit -ExecutionPolicy Bypass -File "${ps1Path}"`, ...)
```
**Fix:** Use `spawn` with args array: `spawn('wt.exe', ['--', 'powershell', '-NoExit', '-ExecutionPolicy', 'Bypass', '-File', ps1Path], { shell: false })`.

### S4 — NEW — cmd.exe metachar injection in launch-headless via `plan`
**Severity:** Critical
**File:** `app/api/agent-teams/route.ts:1187–1197`
**Description:** `launch-headless` takes a user-supplied `plan` string, applies `replace(/"/g, '\\"')`, then passes it to `spawn('cmd.exe', ['/c', cmdToExecute])`. This escape is incorrect for cmd.exe: backslash-escaping double quotes is a POSIX-shell convention. In cmd.exe `/c` mode, `\"` is not a safe escape — a crafted `plan` value such as `foo" & del /q * & echo ` can break out of the quoted string and execute arbitrary commands in `projectPath` with full Node.js server privileges.
```ts
// VULNERABLE:
const safePrompt = fullPrompt.replace(/"/g, '\\"');   // cmd.exe ignores backslash escaping
const cmdToExecute = `claude --dangerously-skip-permissions -p "${safePrompt}"`;
const child = spawn('cmd.exe', ['/c', cmdToExecute], { cwd: projectPath, ... });
```
**Fix:** Eliminate cmd.exe entirely — spawn claude directly:
```ts
const child = spawn('claude', ['--dangerously-skip-permissions', '-p', fullPrompt], {
  cwd: projectPath, shell: false,
  env: { ...process.env, CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS: '1' },
});
```

### S5 — NEW — Unvalidated `agentCount` injected into shell strings
**Severity:** Critical
**File:** `app/api/agent-teams/route.ts:967, 1067, 1124, 1187`
**Description:** `agentCount` is taken from the request body with no type check, range check, or sanitisation, then concatenated into `agentFlag` and inserted into shell strings and tmux `send-keys` commands. A value of `1 && rm -rf ~ #` propagates directly into the executed command string.
```ts
const { action, projectPath, plan, agentCount } = body;    // no validation
const agentFlag = agentCount ? ` --agents ${agentCount}` : '';  // unescaped user value in shell string
// later in tmux script (line 1124):
`  tmux send-keys -t "$SESSION" '/build-with-agent-team ${safePlan}${agentFlag}' Enter`
```
**Fix:** Validate before use: `if (agentCount !== undefined && (!Number.isInteger(agentCount) || agentCount < 1 || agentCount > 10)) return 400;`

## High Findings

### S6 — REPEAT (H2) — projectPath not validated against homedir boundary (commit, analyze, context)
**Severity:** High
**File:** `app/api/commit/route.ts:12–27`, `app/api/analyze/route.ts:9,22`, `app/api/context/route.ts:13–19`
**Description:** `projectPath` is accepted from the POST body and used directly as the `cwd` for git commands and as a base for file system reads/writes. There is no check that the path falls within `os.homedir()` or any whitelist. An attacker can target `C:\Windows\System32`, `/etc`, or any directory accessible to the Node process.
**Fix:**
```ts
import os from 'os';
import path from 'path';
const home = os.homedir();
const resolved = path.resolve(projectPath);
if (!resolved.startsWith(home + path.sep) && resolved !== home) {
  return NextResponse.json({ error: 'Path outside allowed boundary' }, { status: 403 });
}
```

### S8 — NEW — Unrestricted filesystem enumeration in fs/route.ts
**Severity:** High
**File:** `app/api/fs/route.ts:17, 27–40`
**Description:** The directory browser accepts any `path` value, resolves it with `path.resolve()` (which normalises but does not restrict), and returns a full directory listing. An attacker can browse `/etc`, `C:\Users`, `~/.ssh`, or any other path accessible to the Node process. While only directory names are returned (not file contents), this maps the entire machine's directory tree and can inform further attacks via `analyze` or `context` routes.
```ts
currentPath = path.resolve(currentPath);          // resolves but does not restrict
files = fs.readdirSync(currentPath, { withFileTypes: true }); // any path
```
**Fix:** Apply the same homedir boundary check (S6 pattern) before performing the directory read.

### S9 — NEW — CSRF: no protection on mutating POST routes
**Severity:** High
**File:** All routes — commit, terminal, agent-teams, context, analyze, fs
**Description:** All routes accept JSON-body POST requests and perform state-changing operations (git commits, file writes, terminal spawning, filesystem reads) with no CSRF token, no `Origin`/`Referer` validation, and no `SameSite` cookie enforcement. A malicious webpage can make a cross-origin `fetch` POST to `http://localhost:3000/api/agent-teams` that the browser will execute silently. This enables a drive-by commit, arbitrary file write (context sync), or UAC elevation prompt (install-wsl) triggered by visiting a hostile site while the app is running.

Prior finding H3 called out the UAC-specific case; this finding extends it to all mutating routes.

**Fix (layered):**
1. **Short-term:** Validate the `Origin` header — reject requests where `Origin !== 'http://localhost:3000'`.
2. **Medium-term:** Add a CSRF token (set in a `HttpOnly` cookie, submitted as a request header). Enforce in Next.js middleware.

### S10 — NEW — Single-quote injection in WSL bash script via wslProject
**Severity:** High
**File:** `app/api/agent-teams/route.ts:1109`
**Description:** `wslProject` (derived from user-supplied `projectPath` via `toWslPath()`) is embedded inside single quotes in the generated `.sh` script without escaping. In bash, single-quoted strings allow no escape sequences — a literal `'` character terminates the string and anything after becomes executable code. Note: the PowerShell path at line 1153 does apply single-quote escaping (`projectPath.replace(/'/g, "''")`), making this asymmetry clear.
```ts
// VULNERABLE (line 1109):
`cd '${wslProject}'`   // no single-quote escaping
// SAFE (line 1153):
`Set-Location '${projectPath.replace(/'/g, "''")}'`
```
**Fix:** Apply the same escaping before embedding in the bash script:
```ts
const escapedWslProject = wslProject.replace(/'/g, "'\\''");
`cd '${escapedWslProject}'`
```

## Medium Findings

### S11 — NEW — Information disclosure: raw `error.message` in all 500 responses
**Severity:** Medium
**File:** commit:42, terminal:58, agent-teams:1331, analyze:150, context:67, fs:52
**Description:** Every catch block returns `error.message` verbatim in the JSON response. Node.js error messages routinely include full filesystem paths (`ENOENT: no such file or directory, open '/home/aguir/.ssh/...'`), installed software details, and git internals. This data is useful to an attacker profiling the system.
**Fix:** Log full error server-side; return a generic message to the client:
```ts
console.error('[commit] error:', error);
return NextResponse.json({ error: 'Internal server error' }, { status: 500 });
```

### S12 — NEW — No content size limit in context/route.ts sync action
**Severity:** Medium
**File:** `app/api/context/route.ts:44–61`
**Description:** The `sync` action writes user-supplied `content` to three files on disk with no maximum size enforced. An attacker can POST a payload large enough to fill available disk space. Next.js has a default 4 MB body limit but this should be explicitly enforced at the route level.
**Fix:**
```ts
if (typeof content !== 'string' || content.length > 500_000) {
  return NextResponse.json({ error: 'Content too large' }, { status: 413 });
}
```

---

### S13 — NEW — Arbitrary package.json read and parsed into server memory (analyze)
**Severity:** Medium
**File:** `app/api/analyze/route.ts:61–104`
**Description:** `package.json` at the caller-supplied `projectPath` is read with `fs.readFileSync` and parsed with `JSON.parse` without size checking. If `projectPath` points to a crafted directory with a malformed or very large `package.json`, the parse runs in the server process. This amplifies the risk of path traversal (S6) — any file at the target path is read into server memory. Separately, iterating untrusted `dependencies` keys with no output encoding could produce misleading or oversized JSON responses.
**Fix:** Combine with S6 (path boundary). Additionally cap file size:
```ts
const stat = fs.statSync(packageJsonPath);
if (stat.size > 1_000_000) throw new Error('package.json too large');
```

## Low Findings

### S14 — NEW — `action` field not explicitly allowlisted in agent-teams route
**Severity:** Low
**File:** `app/api/agent-teams/route.ts:964–1329`
**Description:** The route uses a chain of `if (action === '...')` branches. An unknown `action` value falls through to line 1329 returning `{ error: 'Invalid action' }`. Functionally safe today, but there is no central allowlist — any new branch added in the future silently becomes an API endpoint without requiring a deliberate allowlist update.
**Fix:** Declare an explicit Set at the top of the handler:
```ts
const ALLOWED_ACTIONS = new Set([
  'check-status','enable','install-skill','launch-terminal',
  'launch-headless','check-wsl','install-wsl','install-distro','install-tmux'
]);
if (!ALLOWED_ACTIONS.has(action)) {
  return NextResponse.json({ error: 'Invalid action' }, { status: 400 });
}
```
