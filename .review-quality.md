### Q1 — REPEAT (H6)
**Severity**: High
**File**: `tsconfig.json:11`
**Description**: `"strict": false` — TypeScript strict mode explicitly disabled. Suppresses `strictNullChecks`, `noImplicitAny`, `strictFunctionTypes`, `strictBindCallApply`, and 6 other checks. All `any`-typed paths, null deref risks, and unsafe casts go undetected.
**Fix**: Change `"strict": false` → `"strict": true`. Expect a handful of compile errors to surface (null-checks on `wslStatus`, `lastCommitMsg`, catch-clause `err` types); fix each individually.

### Q3 — REPEAT (M4)
**Severity**: Medium
**File**: `components/layout/FolderBrowser.tsx:68–71`, `components/layout/HowToUse.tsx:22–25`
**Description**: Both modals guard with `if (!isOpen) return null` **before** `<AnimatePresence>`. When `isOpen` flips to `false`, the component returns `null` immediately — `AnimatePresence` never receives the child with the `exit` prop, so no exit animation plays; the modal vanishes instantly.
**Fix**: Remove the early-return guard and let `AnimatePresence` own visibility via a conditional child:
```tsx
return (
  <AnimatePresence>
    {isOpen && (
      <div className="fixed inset-0 ...">
        <motion.div
          key="modal"
          initial={{ opacity: 0, scale: 0.95, y: 10 }}
          animate={{ opacity: 1, scale: 1, y: 0 }}
          exit={{ opacity: 0, scale: 0.95, y: 10 }}
          ...
        >
          ...
        </motion.div>
      </div>
    )}
  </AnimatePresence>
);
```

### Q4 — NEW
**Severity**: Medium
**File**: `app/context/page.tsx:122–126`
**Description**: The mount `useEffect` auto-loads context with an empty dep array `[]` (suppressed with `// eslint-disable-line`). At component mount, `projectPath` is still `''` because `WorkspaceProvider` restores it from `localStorage` in **its own** `useEffect` — which fires in the same batch but after children's effects. Result: navigating directly to `/context` with a saved workspace silently skips the auto-load.
**Fix**: Add `projectPath` to the dep array and guard against re-firing after the first successful load:
```tsx
const hasMounted = useRef(false);
useEffect(() => {
  if (projectPath && !hasMounted.current) {
    hasMounted.current = true;
    handleLoadContext(projectPath);
  }
}, [projectPath]); // no eslint-disable needed
```

### Q6 — NEW
**Severity**: Low
**File**: `components/layout/WorkspaceProvider.tsx:57–61`
**Description**: `setSyncStatus` schedules `setSyncStatusRaw(null)` via `setTimeout` but never stores the handle. If the component unmounts while the timer is pending, the callback fires on a dead component (React 18 logs a warning; future versions may treat this as an error). Also, if `setSyncStatus` is called again before the 3 s timer fires, the old timer still runs and clears the new status prematurely.
**Fix**: Store and cancel the timer:
```tsx
const clearTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null);
const setSyncStatus = useCallback((msg: string | null) => {
  if (clearTimerRef.current) clearTimeout(clearTimerRef.current);
  setSyncStatusRaw(msg);
  if (msg) {
    clearTimerRef.current = setTimeout(() => setSyncStatusRaw(null), 3000);
  }
}, []);
useEffect(() => () => { if (clearTimerRef.current) clearTimeout(clearTimerRef.current); }, []);
```

### Q7 — NEW
**Severity**: Low
**File**: `components/features/AgentTeams.tsx:84–87`
**Description**: `flash()` calls `setSyncStatus(msg)` then manually schedules `setSyncStatus(null)` after 3 s. But `setSyncStatus` in `WorkspaceProvider` already auto-clears after 3 s internally. The two timers race: if a second `flash()` fires within 3 s of the first, the first timer clears the second message early.
**Fix**: Remove the redundant timer from `flash`:
```tsx
const flash = (msg: string) => setSyncStatus(msg);
```

### Q10 — NEW
**Severity**: Low
**File**: `components/layout/FolderBrowser.tsx:57`
**Description**: `useEffect(() => { if (isOpen) fetchDirectory(initialPath); }, [isOpen, initialPath])` omits `fetchDirectory` from the dependency array. `fetchDirectory` is an inline function recreated each render. Currently harmless because the effect only fires on `isOpen`/`initialPath` changes, but violates the exhaustive-deps rule and is a correctness hazard if the function gains external deps.
**Fix**: Wrap `fetchDirectory` in `useCallback` with its dependencies, then include it in the effect dep array.
