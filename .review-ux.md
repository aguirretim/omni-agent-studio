## Findings

### REPEAT Findings (prior open, unresolved)

**U1 — REPEAT of M4/C6 — Critical**
`components/layout/HowToUse.tsx:22` and `components/layout/FolderBrowser.tsx:68`
`if (!isOpen) return null` fires BEFORE the `<AnimatePresence>` wrapper on the next line. The component unmounts immediately when `isOpen` goes false — framer-motion never observes the exit state, so `exit` props on `<motion.div>` never execute. Elements are removed from the DOM with zero transition.
Fix: Remove the early-return guard. Move the conditional inside AnimatePresence:
```tsx
return (
  <AnimatePresence>
    {isOpen && (
      <div className="fixed inset-0 z-50 ..." onClick={onClose}>
        <motion.div
          initial={{ opacity: 0, scale: 0.95, y: 10 }}
          animate={{ opacity: 1, scale: 1, y: 0 }}
          exit={{ opacity: 0, scale: 0.95, y: 10 }}
          onClick={(e) => e.stopPropagation()}
        >
```

---

**U2 — REPEAT of C5 — Critical**
`components/layout/HowToUse.tsx:27`, `components/layout/FolderBrowser.tsx:73`
Both modal inner containers (`<motion.div>`) have no `role="dialog"`, `aria-modal="true"`, or `aria-labelledby`. Screen readers cannot identify these as dialogs, will not announce them on open, and allow the virtual cursor to roam content behind the backdrop.
Fix: Add to each inner `<motion.div>`:
```tsx
role="dialog"
aria-modal="true"
aria-labelledby="how-to-use-title"   // or "folder-browser-title"
```
Add matching `id` to the `<h2>` in each modal header.

---

**U3 — REPEAT of H7 — High**
`components/layout/HowToUse.tsx` (entire component), `components/layout/FolderBrowser.tsx` (entire component)
No focus trap: keyboard users can Tab out of an open modal and interact with sidebar nav and header buttons while the modal overlays. Focus is not moved into the modal on open and not restored to the trigger button on close.
Fix: On open, call `modalRef.current?.focus()`. Intercept Tab/Shift+Tab to cycle within focusable children. On close, call `triggerRef.current?.focus()` (AppShell HelpCircle button for HowToUse; FolderBrowser open button for FolderBrowser).

---

**U4 — REPEAT of H8 — High**
`components/layout/HowToUse.tsx:26`, `components/layout/FolderBrowser.tsx:72`
The backdrop `div` has no `onClick` handler. Clicking outside the modal panel does nothing. Standard modal UX and ARIA authoring practices require backdrop click to close.
Fix: `<div className="fixed inset-0 ..." onClick={onClose}>` with `onClick={(e) => e.stopPropagation()}` on the inner panel (resolved together with U1 fix above).

---

**U5 — REPEAT of H10 — High**
`components/features/AgentTeams.tsx:298-311`
The tab row `<div>` has no `role="tablist"` and the four tab buttons have no `role="tab"`, `aria-selected`, or `aria-controls`/`id` pairing. Screen readers announce these as plain buttons. Arrow-key navigation (required by ARIA Tabs pattern) is absent.
Fix:
```tsx
<div role="tablist" aria-label="Agent Teams sections" className="flex border-b ...">
  <button
    role="tab"
    id={`tab-${tab}`}
    aria-selected={activeTab === tab}
    aria-controls={`panel-${tab}`}
    ...
  >
</div>
<div role="tabpanel" id={`panel-${activeTab}`} aria-labelledby={`tab-${activeTab}`} tabIndex={0}>
  {/* active tab content */}
</div>
```
Add Left/Right arrow key handlers to cycle activeTab.

---

**U6 — REPEAT of H11 — High**
`components/ui/StatusToast.tsx:12`
The animated status pill has no `role="status"` or `aria-live`. When `syncStatus` updates ("Launching tool…", "claude online", "Failed launching…"), screen readers receive no announcement.
Fix:
```tsx
<motion.div role="status" aria-live="polite" aria-atomic="true" ...>
```

**U7 — REPEAT of H12 — Medium**
`app/sessions/page.tsx:90`
`<CheckCircle2 className="text-emerald-500">` is hardcoded unconditionally. A failed commit ("Failed: …", "Fatal: …") renders the same green checkmark as a success.

```tsx
const isError = lastCommitMsg?.startsWith('Failed') || lastCommitMsg?.startsWith('Fatal');
// Render XCircle + text-red-400 for errors, CheckCircle2 + text-emerald-500 for success
```

### NEW Findings

**U8 — NEW — High**
`components/layout/AppShell.tsx:27-68`
The sidebar is always rendered at `w-[260px] flex-shrink-0` with no responsive breakpoints. On mobile viewports (~375px wide) the sidebar consumes 260px, leaving ~115px for page content — completely unusable. There is no hamburger menu, overlay drawer, or `hidden md:flex` pattern anywhere in the layout.
Fix: Hide sidebar at small viewports and add a hamburger toggle:
```tsx
// aside: className="hidden md:flex w-[260px] ..."
// Add mobile hamburger button in header (visible below md:) + overlay state
```

---

**U9 — NEW — High**
Multiple icon-only buttons rely solely on `title` attribute for labeling. `title` is not announced by most screen readers (especially mobile/touch) and is invisible during keyboard navigation.
- `AppShell.tsx:86` — HelpCircle button: `title="How to Use"`, no `aria-label`
- `HowToUse.tsx:41` — Close (X) button: no aria-label at all
- `FolderBrowser.tsx:84` — Close (X) button: no aria-label at all
- `FolderBrowser.tsx:94` — Home button: `title="Home Directory"`, no `aria-label`
Fix: Add `aria-label` to each:
```tsx
<button aria-label="Open how-to-use guide" ...>   // AppShell
<button aria-label="Close dialog" ...>             // both modal X buttons
<button aria-label="Go to home directory" ...>     // FolderBrowser Home
```

---

**U10 — NEW — Medium**
`components/layout/AppShell.tsx:47-59`
Active nav `<Link>` items highlight via CSS but have no `aria-current="page"`. Screen readers use `aria-current` to announce the current page within a nav landmark.
Fix:
```tsx
<Link aria-current={isActive ? 'page' : undefined} ...>
```

---

**U11 — NEW — Medium**
`components/layout/AppShell.tsx:27,42`
The `<aside>` and `<nav>` landmarks have no accessible names. When a page has multiple landmark regions, WCAG requires labelling them so screen reader users can distinguish via landmark navigation.
Fix:
```tsx
<aside aria-label="Main navigation" ...>
<nav aria-label="Primary" ...>
```

---

**U12 — NEW — Medium**
`components/features/AgentTeams.tsx:259-284`
The expand/collapse panel button does not set `aria-expanded`. The visual chevron conveys state but screen readers cannot programmatically determine the panel's expanded/collapsed state.
Fix:
```tsx
<button
  aria-expanded={isExpanded}
  aria-controls="agent-teams-content"
  ...>
<motion.div id="agent-teams-content" ...>
```

---

**U13 — NEW — Medium**
`components/features/AgentTeams.tsx:381-396`
The agent count selector (Auto / 2 / 3 / 4 / 6) lacks group semantics. The "Agents" text at line 381 is a plain `div` not associated with the button group. Buttons have no `aria-pressed` — selection state is color-only.
Fix:
```tsx
<div role="group" aria-labelledby="agent-count-label">
  <span id="agent-count-label" className="...">Agents</span>
  {(['auto', 2, 3, 4, 6] as const).map(n => (
    <button aria-pressed={agentCount === n} ...>
  ))}
</div>
```

---

**U14 — NEW — Medium**
`components/features/SplitPanePreview.tsx:103-129`
The animated terminal mosaic is purely decorative (simulated, not real agent output) but is not marked `aria-hidden="true"`. Screen readers will attempt to read continuously-cycling terminal lines, generating a stream of disruptive announcements.
Fix:
```tsx
<div aria-hidden="true" className="rounded-xl ...">
  {/* mosaic grid */}
</div>
<p className="sr-only">Preview of four agent terminal panes running simultaneously in split-pane mode</p>
```

---

**U15 — NEW — Medium**
`components/ui/ToolCard.tsx:72-81`
The "Check usage" `<a>` opens in `target="_blank"` with no indication to screen readers that navigation opens a new window. WCAG 2.4.4 (Link Purpose) requires communicating this.
Fix:
```tsx
<a aria-label={`Check ${name} usage (opens in new tab)`} target="_blank" ...>
```

---

**U16 — NEW — Low**
`components/layout/AppShell.tsx:66`
The online status dot (`bg-emerald-500 rounded-full`) is purely visual with no accessible text equivalent. Screen readers skip it entirely.
Fix:
```tsx
<div className="w-2 h-2 rounded-full bg-emerald-500 ..." role="img" aria-label="Status: connected" />
```

---

**U17 — NEW — Low**
`components/features/AgentTeams.tsx:25-35` (StatusBadge component)
Each StatusBadge renders a colored dot to convey ok/not-ok state using color as the only differentiator (emerald vs zinc). Users with color-vision deficiency cannot distinguish the two states.
Fix: Use a distinct character in addition to color:
```tsx
<span className={`w-1.5 h-1.5 rounded-full ${ok ? 'bg-emerald-400' : 'bg-zinc-600'}`} aria-hidden="true" />
// and add sr-only state text:
<span className="sr-only">{ok ? '(active)' : '(inactive)'}</span>
```

---

**U18 — NEW — Low**
Multiple files — `text-zinc-600` at font sizes ≤ 11px
`text-zinc-600` (#52525b) on `bg-[#09090b]` yields approximately 3.7:1 contrast — below WCAG AA 4.5:1 for normal text. At 10–11px the stricter threshold applies (not "large text"). Affected:
- `AppShell.tsx:37` — "Menu" label (`text-[10px]`)
- `AppShell.tsx:65` — version number (`text-[11px]`)
- `AgentTeams.tsx:282` — "Claude Code only" label (`text-[10px]`)
- `AgentTeams.tsx:397` — launch instruction paragraph (`text-[10px]`)
- Multiple small labels in the Setup tab
Fix: Promote to `text-zinc-500` (#71717a, ~4.6:1) minimum for any information-bearing text.

## Prioritized Fix Roadmap (UX)

### Tier 1 — Screen-reader blocking
1. Fix AnimatePresence exit in HowToUse + FolderBrowser — move guard inside AnimatePresence (U1)
2. Add role="dialog" + aria-modal + aria-labelledby to both modals (U2)
3. Add focus trap to both modals; restore focus to trigger on close (U3)
4. Add backdrop onClick={onClose} to both modals (U4)
5. Add role="status" + aria-live="polite" to StatusToast (U6)
6. Add role="tablist" / role="tab" / aria-selected + arrow-key nav to AgentTeams tabs (U5)

### Tier 2 — Correctness and usability
7. Add aria-label to all icon-only buttons (U9)
8. Fix sessions/page.tsx error icon (U7)
9. Add aria-expanded + aria-controls to AgentTeams collapse button (U12)
10. Add aria-current="page" to active nav links (U10)
11. Add aria-label to aside/nav landmarks (U11)
12. Add aria-hidden + sr-only description to SplitPanePreview mosaic (U14)
13. Add role="group" + aria-pressed to agent count selector (U13)
14. Add new-tab aria-label to ToolCard external links (U15)

### Tier 3 — Mobile and polish
15. Add responsive sidebar — hidden on mobile, hamburger toggle (U8)
16. Upgrade text-zinc-600 to text-zinc-500 minimum for information-bearing small text (U18)
17. Add role="img" + aria-label to status dot (U16)
18. Add sr-only state text to StatusBadge colored dots (U17)
